# PACDS evaluation findings (2026-09-28)

Continues `2026-09-27-findings.md` with the Debezium case set and the support agent. LLM: `gpt-6-luna`
(OpenCode Go, Responses API) for PACDS, the no-code baseline and the support agent. Baseline = same model, same
question, report and logs only, no code.

The runs before 2026-09-28T14:30 were not traced or archived: these numbers are their only record. Later runs
are archived in S3 (`python -m tests.eval_run list`).

## 1. Test bed

- **Debezium candidates** (`tests/replay/candidates/debezium-*/`, rophy/pacds#1): 121 fixtures from the Debezium
  Google Group, plus 7 rejected (`rejected.json`). Run with `--candidates`.
- **Catalog**: `tests/replay/CATALOG.md`, generated by `python -m tests.replay.catalog [--check] [--after DATE]`:
  source, date, set, class, review tier, baseline p(truth), per-model training-cutoff marks.
- **Labels**: the 51 candidates the baseline gets wrong were reviewed twice, blind (`reviews` in `case.json`):
  tier `certain` 18, `probable` 33; classes A 1, B 31, C 13, D 6. The other 70 are `unreviewed` (the baseline
  gets them right).
- **Caveat**: Debezium group reporters operate everything themselves, so B (user error) and C (infrastructure) are
  inherently blurry.

## 2. Results

**Old GitHub replay set (23 cases)**: the clear set is 12/12 for every configuration, so it carries no signal;
keep it only as a no-harm check. Hard set (11): PACDS fixed question 7/11, baseline 5/11, support agent with
PACDS 9/11, without 7/11.

**Debezium, 51 reviewed cases, support agent, 3 runs each** (run 2026-09-28T08:44, before PACDS had git history
and before the second round of playbook steps):

| Class | runs | with PACDS | without |
|---|---|---|---|
| A | 3 | 33% | 33% |
| B | 93 | 65% | 51% |
| C | 39 | 23% | 15% |
| D | 18 | 11% | 11% |
| all | 153 | **47%** | **37%** |

Per case (right in at least 2 of 3 runs): 23 vs 19 of 51; PACDS gained 7 cases and lost 3. The baseline on the
same labels: about 20%.

**Run after adding PACDS history and the playbook steps (2026-09-28T11:40): inconclusive.** OpenCode Go's
5-hour usage limit was hit; only 88 of 153 tickets with PACDS finished (43%; D 3/8, C 3/24). PACDS used the new
tools heavily (587 `git_log`, 224 `git_show`).

## 3. Miss analysis (hand-classified from transcripts, run 08:44)

- **D misses (18)**: `pacds_wrong` 8 (PACDS confidently denied regressions: the code looked deliberate and it had
  no history then), `wrong_questions` 5, `agent_overrode` 3, `defensible` 2.
- **C misses (30)**: `wrong_questions` 13 (the agent never asked *who controls the failing setting*: DB grants,
  publications, topic config, platform classpath), `agent_overrode` 8, `no_pacds` 5, `pacds_wrong` 2,
  `defensible` 2.

These led to the playbook changes (classify by where the fix is made; boundary rules; regression step; "whose
fix is it" step) and to PACDS's `git_log`/`git_show` tools.

## 4. Cost

A full run (51 × 3, both variants) is about 30M input tokens, 27M of them PACDS (208 investigations, average 130K
input, median 6 turns). An estimated 79% of PACDS input is earlier tool results resent every turn
(`search_code` and `read_file` dominate).

The first traced run (`20260928T-phase1-check`, 8 PACDS requests) shows OpenCode Go already caches about 67% of
PACDS input tokens. The resend share therefore overstates the cost by however much cached tokens are discounted;
the phase 2 cost report should measure it from traces.

## 5. Providers

- **OpenCode Go** (`gpt-6-luna`, training cutoff 2026-05-18, Responses API, header `x-opencode-session`): works;
  its 5-hour usage window caps full runs, so split a full run across windows.
- **Plugsky** (`https://plugsky.com/v1`, chat completions, credential injected by the proxy): the account is on a
  trial plan capped at `plugsky-plus`. `plugsky-plus`/`-pro` are Nemotron 3 Nano Omni 30B-A3B (reasoning);
  `plugsky-max` is Nemotron 3 Ultra 550B. Fallback models are silent; responses report only the tier name. Needs
  `LLM_MAX_OUTPUT_TOKENS=16000` (otherwise "final answer did not complete: length"); about 12% of JSON-format
  calls return 502 (now retried). First pilot (before those fixes, concurrency 4): baseline 87/153 failed, 9/66
  right. Run it with, e.g.
  `env LLM_BASE_URL=https://plugsky.com/v1 LLM_MODEL=plugsky-plus LLM_API= LLM_SESSION_HEADER= LLM_API_KEY=x LLM_MAX_OUTPUT_TOKENS=16000 ./scripts/eval.sh ...`
